# Stress Tester Pro

Инструмент для автоматического стресс-тестирования решений олимпиадных задач.
Сравнивает вывод вашего решения с эталонной программой на большом количестве
случайных тестов и показывает, на каких входных данных ответы расходятся.

## Возможности

- **Brute Force** — генератор создаёт тест, решение и эталон запускаются на
  одинаковых входных данных, выводы сравниваются.
- **Interactive** — решение и интерактор общаются через stdin/stdout,
  интерактор выносит вердикт.
- Поддержка C++, Python, Java, Pascal, Rust, Kotlin, D, JavaScript, Ruby.
- Настройка количества тестов, таймаута, остановки при первой ошибке.
- Сохранение и загрузка конфигураций (JSON).
- Тёмная и светлая темы оформления.
- Вкладки: общий лог, проваленные тесты, ошибки.
- Прогресс-бар, остановка тестирования в любой момент.

## Установка и запуск

Требования:
- Python 3.8 или новее
- PyQt5
- Компиляторы/интерпретаторы тех языков, которые вы собираетесь тестировать,
  должны быть установлены и доступны в PATH.

```bash
pip install PyQt5
python3 main.py
```

## Как писать программы для тестирования

Инструмент запускает **три разных программы** (в режиме Brute Force) или
**две** (в режиме Interactive). Каждая программа — самостоятельный исполняемый
файл или скрипт.

### 1. Решение (Solution)

Программа, которую вы тестируете. Читает входные данные из стандартного
потока ввода (`stdin`), выводит ответ в стандартный поток вывода (`stdout`).

Пример (задача A+B):
```python
a, b = map(int, input().split())
print(a + b)
```

### 2. Эталон (Brute) / Интерактор (Interactor)

- **Brute Force:** эталонная программа, которая гарантированно выдаёт
  правильный ответ. Интерфейс такой же, как у решения: `stdin` → `stdout`.
- **Interactive:** программа-интерактор. Она **первой** выводит данные в
  `stdout`, затем читает ответы решения из `stdin`, снова выводит данные, и
  так далее. Когда интерактор определяет, что решение отработало верно, он
  завершается с кодом `0`. Если решение ошиблось — с любым ненулевым кодом.

**Важно:** интерактор обязан принимать **seed** (целое число) как первый
аргумент командной строки. Используйте его для инициализации генератора
случайных чисел — это гарантирует воспроизводимость тестов.

Пример интерактора (угадай число, C++):
```cpp
int main(int argc, char** argv) {
    unsigned long long seed = strtoull(argv[1], nullptr, 10);
    srand(seed);
    int n = rand() % 100;
    cout << n << endl;          // первое сообщение — решение получает N
    int x = rand() % (n + 1);
    while (true) {
        int r;
        cin >> r;
        if (r < x) cout << -1 << endl;
        else if (r == x) { cout << 0 << endl; return 0; }
        else cout << 1 << endl;
    }
}
```

### 3. Генератор (только для Brute Force)

Программа, которая выдаёт случайный тест в `stdout`. Никаких аргументов
командной строки не требуется. Каждый запуск должен генерировать новый тест.

Пример:
```python
import random
print(random.randint(1, 100), random.randint(1, 100))
```

## Интерпретация результатов

После завершения тестирования вы видите три вкладки:

- **Console** — общий лог: компиляция, прогресс, итоговая статистика.
- **Failed tests** — тесты, на которых вывод решения не совпал с эталоном
  (Brute Force) или интерактор вернул ненулевой код (Interactive).
  Для каждого теста показаны:
  - входные данные
  - вывод решения
  - вывод эталона (или лог общения в интерактивном режиме)
- **Errors** — ошибки выполнения: генератор/решение/эталон упали с
  исключением, превышен таймаут, программа зависла.

Возможные сообщения об ошибках:
- `timeout — Solution hung` — решение не завершилось за отведённое время.
- `solution finished, interactor left waiting` — решение завершилось, а
  интерактор продолжал ждать ответ (скорее всего, решение недочитало данные).
- `interactor finished, solution left waiting` — обратная ситуация.
- `interactor exited with code X` — интерактор вернул ненулевой код (тест
  не пройден).


## Сборка в исполняемый файл (Windows)

```bash
pip install pyinstaller
pyinstaller --onefile --windowed --name "StressTester" main.py
```

Исполняемый файл появится в папке `dist/` и не требует установленного Python.
